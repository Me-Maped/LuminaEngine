## 5. Interaction 功能测试矩阵

先在单线程版本通过，再考虑并行化。以下“预期”是课程的目标行为，需要你自己实现，不是引擎对 Interaction 的现成保证。

| 场景 | 目标行为 | 结果 / 证据 |
| --- | --- | --- |
| 场景没有目标 | 不触发事件，不访问无效 handle | 未执行 |
| 一个范围内目标 | 选中并能触发一次交互 | 未执行 |
| 多个候选目标 | 按文档约定选择，结果可解释 | 未执行 |
| 目标距离相同 | tie-break 规则明确且测试覆盖 | 未执行 |
| 目标 disabled | 不进入候选集合 | 未执行 |
| 距离非法 | Editor 给出诊断或 runtime 明确拒绝 | 未执行 |
| 目标扫描后被销毁 | 执行前重新验证，安全放弃 | 未执行 |
| 组件被移除 | 不保留失效 component 指针 | 未执行 |
| 连续输入 | 按约定触发；无重复订阅导致的额外调用 | 未执行 |
| 两个 World | 状态隔离，不串用 registry/entity | 未执行 |
| 停止并重新开始 PIE | 无遗留状态或重复回调 | 未执行 |
| 切换/销毁 World | 清空缓存、解绑事件、处理未完成工作 | 未执行 |
| 保存并重开 | 持久字段恢复；临时状态重新计算 | 未执行 |
| C# reload | 重建必要状态，旧引用不再使用 | 未执行 |
| 正常关闭 Editor | 关闭回调执行，无生命周期错误 | 未执行 |

不要把 C# reload、停止 PIE、重新启动 Editor 和 native module hot unload 当作同一件事。没有实现支持时，C++ 修改后关闭 Editor 再重新构建。

“关闭插件”测试需分清两种情况：

- 宿主无静态依赖的可选插件：禁用后应能独立运行。
- 宿主显式链接并调用插件 API：禁用前必须移除或条件化依赖与调用。不要要求构建系统凭空消除硬依赖。

## 8. 最终验收

- [ ] 能在不看教程的情况下创建一个 module，解释 descriptor、Build.cs 与 target 的关系。
- [ ] Runtime 与 Editor 依赖方向正确，public API 不泄漏 Editor 类型。
- [ ] 每个缓存都有明确 owner 和失效时机。
- [ ] 每次订阅/注册都有对应解绑/注销。
- [ ] World 关闭前处理完 task 与 deferred work，不假定 module unload 自动解决生命周期。
- [ ] 组件查询、目标销毁、保存重开、脚本 reload 有证据。
- [ ] 打包 Game 实际启动并演示功能。
- [ ] 插件可在第二个项目使用。
- [ ] README 说明安装、依赖、示例、限制和已测试环境。
- [ ] 核心逻辑有测试；未测试平台和功能明确列出。
